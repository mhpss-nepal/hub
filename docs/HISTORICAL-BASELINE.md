# Historical baseline reading mode

The dashboard opens on a historical-source shell, with no data embedded in the public page. The synthetic demonstration remains a separate, explicit source. The register can still be requested through the existing access panel; `?source=live` permits its existing signed-in auto-open path. `?source=choose` retains the source chooser.

## Private file workflow

1. Obtain the minimized historical-summary JSON through the owner's approved private channel. Do not use a raw register, master workbook or full record export here.
2. Open the dashboard and choose that file under Historical baseline.
3. Inspect the source version, original export date, retained backup capture, units and limitations.
4. Export the private aggregate summary CSV if required. Keep that file private too.
5. Clear the historical view or close/reload the page to remove its in-memory values.

This mode adds a separate aggregate presentation adapter. It does not call the operational collector, device record store, queue, database reader or publisher. Historical entries are not new sessions. Contacts are not unique people; unknown counts are not zero. Later form entries are unverified and are not included in historical contact totals. Organisation, geographic coverage, trend and age/sex panels are unavailable rather than filled with fabricated values. No combined achievement is calculated.

## Public/private boundary

The public repository contains only the source-selection interface, strict summary schema validator and presentation/export code. The owner-private master, summary, standalone viewer and review evidence are retained outside this repository. No baseline record IDs, rows, location/organisation/time cells, source-host paths, hashes or private counts are shipped in the new public files. Page login cannot protect publicly hosted assets.

The importer requires an exact key set, safe nonnegative integer counts, expected unit/classification/version and a bounded file size. It rejects full record exports and extra fields, clears stale figures on refusal, and fences delayed file reads against a later selection or Clear. This validates structure, not authorship: the file's provenance must be checked through the private delivery manifest. There is no server attestation or institutional approval implied by a file being accepted.

The existing menu, five-colour palette, operational formulas/exports, authentication, storage, data schema and shared runtime assets remain unchanged. No service worker belongs to this Hub repository; this change does not modify the separate field application's cache or pending records.
